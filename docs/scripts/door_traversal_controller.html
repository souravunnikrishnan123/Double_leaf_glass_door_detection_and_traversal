Closed-loop door traversal controller for Unitree Go1.

States: - TRAVERSE_DOOR - ABORT - DONE

Responsibilities: - Subscribe to odometry - Consume door passability results - Generate cmd_vel - Decide when door traversal is complete - Abort safely if corridor becomes unsafe

  49    Control the robot while it aligns with and traverses a door corridor.
  50
  51    The controller consumes corridor geometry and passability updates, applies
  52    confirmation hysteresis, aligns the robot in stages, and continuously
  53    checks clearance while crossing and moving beyond the door. Recovery states
  54    either back the robot away from an unsafe corridor or ask the passability
  55    node to define a temporary corridor around a newly observed obstruction.
  56

  58    the robot frame to world-frame twists and sent through
  59    ``/gazebo/set_model_state``.

 328    def odom_callback(self, msg):
 329        """
 330        Cache the robot's planar pose from an odometry message.
 331
 332        Args:
 333            msg:
 334                ROS ``Odometry`` message containing position and quaternion
 335                orientation.
 336
 337        Notes:
 338            Roll, pitch, altitude, covariance, and twist are intentionally
 339            ignored because the controller operates in the ground plane.
 340        """
 341        p = msg.pose.pose.position
 342        q = msg.pose.pose.orientation
 343
 344        self.current_pose = (p.x, p.y)
 345
 346        quat = [q.x, q.y, q.z, q.w]
 347        _, _, yaw = euler_from_quaternion(quat)
 348        self.current_yaw = yaw

 350    def passability_callback(self, msg):
 351        """
 352        Update corridor geometry and filter the latest passability result.
 353
 354        ``type_of_passability_check`` selects one of two independent results.
 355        Type ``1`` verifies clearance through and beyond the corridor midpoint;
 356        type ``2`` verifies only the minimum local clearance. Consecutive safe
 357        or unsafe samples are required before either stored result changes.
 358
 359        Args:
 360            msg:
 361                ``Robot_passability`` message. Distances are expected in
 362                meters, lateral offsets use the camera or initial-yaw frames
 363                named by their fields, and ``heading_error`` is in radians.
 364
 365        Notes:
 366            Receiving one check type clears the counters and result belonging
 367            to the other type. This prevents a stale local result from being
 368            treated as a current corridor result, or vice versa.
 369        """
 370        self.front_clearance = msg.front_clearance
 371        self.corridor_center_x_robot_base = msg.x_corridor_center_start_yaw_frame
 372        self.x_corridor_center_cam = msg.x_corridor_center_cam
 373        self.distance_to_corridor_mid_point = msg.corridor_middle_point_depth
 374        self.minimum_clearance_beyond_corridor_mid_point = msg.clearance_needed_beyond_mid_corridor
 375        self.heading_error_to_corridor = msg.heading_error
 376
 377        # Raw passability from detector
 378        if msg.type_of_passability_check == 1.0: # corridor passability check
 379            self.local_passable = False  # reset local passability. because we are doing corridor passability check now
 380            self.safe_seq_local = 0
 381            self.unsafe_seq_local = 0
 382            
 383            if self.front_clearance is not None:
 384                if self.front_clearance > self.distance_to_corridor_mid_point +self.minimum_clearance_beyond_corridor_mid_point: # ensure there is enough clearance beyond the corridor mid point, not just at the current position, to avoid the case where the robot is currently in a safe spot but will soon collide with the door frame when it moves forward:
 385                    raw_corridor_passable = True
 386                else: 
 387                    raw_corridor_passable = False
 388            else:
 389                raw_corridor_passable = False
 390
 391            # Apply hysteresis: require consecutive confirmations before toggling
 392            if raw_corridor_passable:
 393                self.safe_seq_corridor += 1
 394                self.unsafe_seq_corridor = 0
 395                if self.safe_seq_corridor >= self.passability_true_hysteresis:
 396                    self.corridor_passable = True
 397                        
 398            else:
 399                self.unsafe_seq_corridor += 1
 400                self.safe_seq_corridor = 0
 401                if self.unsafe_seq_corridor >= self.passability_false_hysteresis:
 402                    self.corridor_passable = False
 403            
 404             
 405        elif msg.type_of_passability_check == 2.0: # local passability check
 406            self.corridor_passable = False  # reset corridor passability. because we are doing local passability check now
 407            self.safe_seq_corridor = 0
 408            self.unsafe_seq_corridor = 0
 409            if self.front_clearance is not None:
 410                if self.front_clearance > self.min_front_clearance_local_passability_check:
 411                    raw_local_passable = True
 412                else: 
 413                    raw_local_passable = False
 414            else:
 415                raw_local_passable = False
 416            
 417            # Apply hysteresis: require consecutive confirmations before toggling                  
 418            if raw_local_passable:
 419                self.safe_seq_local += 1
 420                self.unsafe_seq_local = 0
 421                if self.safe_seq_local >= self.passability_true_hysteresis:
 422                    self.local_passable = True
 423            else:
 424                self.unsafe_seq_local += 1
 425                self.safe_seq_local = 0
 426                if self.unsafe_seq_local >= self.passability_false_hysteresis:
 427                    self.local_passable = False

 433    def model_states_callback(self, msg):
 434        """
 435        Cache the current Gazebo pose of the Go1 model.
 436
 437        Args:

 439                ROS ``ModelStates`` message containing parallel model-name and

 442        Notes:

 474            movement commands. If no Gazebo pose has arrived yet,
 475            :meth:`publish_cmd_vel` logs a warning and returns.
 476        """
 477        self.publish_cmd_vel(0.0, 0.0, 0.0)

 479    def wrap_angle(self, angle):
 480        """
 481        Normalize an angle to the principal signed range.
 482
 483        Args:
 484            angle:
 485                Angle in radians. Scalars and NumPy-compatible arrays are
 486                accepted.
 487
 488        Returns:
 489            The equivalent angle in the half-open range ``[-pi, pi)``.
 490        """
 491        return (angle + np.pi) % (2.0 * np.pi) - np.pi

 494    def publish_cmd_vel(self, v_forward, v_lateral, omega):
 495        """
 496        Apply a robot-frame velocity command to the Gazebo model.
 497
 498        Linear velocity is rotated into the world frame while angular velocity
 499        remains a yaw rate about the world z axis. The latest Gazebo pose is
 500        copied into the request so the service changes velocity without
 501        teleporting the robot.
 502
 503        Args:
 504            v_forward:
 505                Forward velocity in the robot frame, in meters per second.
 506
 507            v_lateral:
 508                Lateral velocity in the robot frame, in meters per second.
 509
 510            omega:
 511                Yaw rate in radians per second.
 512
 513        Raises:
 514            rospy.ServiceException:
 515                If the Gazebo service call fails.
 516
 517        Notes:
 518            The command is skipped when no Gazebo pose has been received. The
 519            world-frame conversion uses the latest odometry yaw.
 520        """
 521
 522        if self.gazebo_pose is None:
 523            rospy.logwarn("Gazebo pose not yet received; cannot publish velocity and angular velocity to /set_model_state service")
 524            return
 525
 526       # DO NOT TOUCH pose at all
 527        self.modelstate.model_name = "go1_gazebo"
 528        self.modelstate.reference_frame = "world"
 529
 530        # always use current gazebo pose
 531        self.modelstate.pose = self.gazebo_pose
 532
 533        # Convert body-frame forward velocity to world frame
 534        # only forward velocity v is given in robot base frame no lateral velocity
 535        #v_lateral is always zero.
 536        vx_world = v_forward * np.cos(self.current_yaw) - v_lateral * np.sin(self.current_yaw)
 537        vy_world = v_forward * np.sin(self.current_yaw) + v_lateral * np.cos(self.current_yaw)
 538
 539        self.modelstate.twist.linear.x = vx_world
 540        self.modelstate.twist.linear.y = vy_world
 541        self.modelstate.twist.linear.z = 0.0
 542
 543        self.modelstate.twist.angular.x = 0.0
 544        self.modelstate.twist.angular.y = 0.0
 545        self.modelstate.twist.angular.z = omega
 546
 547        rospy.loginfo("Publishing cmd_vel: v_forward=%.3f m/s, v_lateral=%.3f m/s, omega=%.3f rad/s", v_forward, v_lateral, omega)
 548
 549        response = self.set_model_state(self.modelstate)
 550        rospy.loginfo(
 551            "Service response: success=%s message=%s",
 552            response.success,
 553            response.status_message
 554        )

 556    def get_forward_displacement(self, ref_pose, ref_yaw):
 557        """
 558        Measure displacement along a fixed reference heading.
 559
 560        The current world-frame translation is projected onto the heading that
 561        was active when the reference pose was recorded. Later yaw corrections
 562        therefore do not change the meaning of the travelled distance.
 563
 564        Args:
 565            ref_pose:
 566                Reference planar position as ``(x, y)`` in meters.
 567
 568            ref_yaw:
 569                Reference heading in radians.
 570
 571        Returns:
 572            Signed forward displacement in meters, or ``0.0`` when current
 573            odometry is not available.
 574        """
 575        if self.current_pose is None:
 576            return 0.0
 577
 578        dx = self.current_pose[0] - ref_pose[0]
 579        dy = self.current_pose[1] - ref_pose[1]
 580
 581        return dx * np.cos(ref_yaw) + dy * np.sin(ref_yaw)

 583    def find_heading_error_estimate(self):
 584        """
 585        Update the motion-based estimate of corridor heading error.
 586
 587        Lateral corridor-center drift is divided by measured forward motion and
 588        passed through a first-order low-pass filter. Updates are accepted only
 589        after enough forward displacement to avoid amplifying stationary
 590        measurement noise.
 591
 592        Notes:
 593            The method updates ``heading_error_est``,
 594            ``heading_estimate_samples``, and ``heading_estimate_valid`` in
 595            place. It does not return the estimate.
 596        """
 597        # Estimate heading error based on change in corridor center x
 598        # =================================================
 599        # Update heading error estimate (from corridor drift and motion-gated)
 600        # =================================================
 601        if (
 602            self.prev_corridor_center_x_robot_base is not None and
 603            self.prev_pose_for_heading is not None and
 604            self.current_pose is not None
 605            ):
 606            # Compute actual forward motion
 607            dx_world = self.current_pose[0] - self.prev_pose_for_heading[0]
 608            dy_world = self.current_pose[1] - self.prev_pose_for_heading[1]
 609
 610            forward_motion = (
 611                dx_world * np.cos(self.current_yaw) +
 612                dy_world * np.sin(self.current_yaw)
 613            )
 614
 615            # Only update heading if robot actually moved forward
 616            if abs(forward_motion) > self.min_forward_motion_for_heading:
 617                lateral_drift = self.corridor_center_x_robot_base - self.prev_corridor_center_x_robot_base
 618                heading_raw = lateral_drift / forward_motion
 619
 620                self.heading_error_est = (
 621                    self.heading_filter_alpha * heading_raw +
 622                    (1.0 - self.heading_filter_alpha) * self.heading_error_est
 623                )
 624                rospy.loginfo(f"Heading error estimate: {self.heading_error_est:.3f} rad")
 625                
 626                self.heading_estimate_samples += 1
 627                if self.heading_estimate_samples >= self.required_heading_samples:
 628                    self.heading_estimate_valid = True
 629
 630                self.prev_corridor_center_x_robot_base = self.corridor_center_x_robot_base
 631                self.prev_pose_for_heading = self.current_pose
 632

 638    def control_loop(self):
 639        """
 640        Run the door-alignment and traversal finite-state machine.
 641
 642        The loop waits for a trigger and valid feedback, performs two heading
 643        alignment stages and one position-alignment stage, turns to the final
 644        corridor heading, traverses the corridor, and continues beyond its
 645        midpoint. Unsafe feedback causes either an abort/back-off or a request
 646        for a virtual corridor, depending on where the robot is in the
 647        sequence.
 648
 649        Raises:
 650            rospy.ServiceException:
 651                If a Gazebo model-state command cannot be delivered.
 652
 653        Notes:
 654            This is a blocking loop intended to run for the lifetime of the
 655            node. It returns after the ``ABORT`` or ``DONE`` state completes,
 656            or when ROS shuts down.
 657        """
 658             
 659
 660        while not rospy.is_shutdown():
 661            if not self.start_movement:# node is activated as there is a corridor to traverse
 662                self.rate.sleep()
 663                continue
 664            
 665            if not self.data_ready():
 666                self.rate.sleep()
 667                continue
 668            
 669        
 670            # =================================================
 671            # IDLE - to wait until temporal smoothing for passability is done
 672            # ================================================= 
 673
 674            if self.state == IDLE:
 675                # Initialize traversal start pose
 676                self.start_pose = self.current_pose
 677                self.start_yaw = self.current_yaw
 678                if not self.corridor_passable:
 679                    rospy.loginfo("IDLE: waiting for temporal smoothing to finish")
 680                    #stay where you are
 681                    self.stop_robot()
 682                    continue
 683                else:#now we are sure the corridor is passable by temporal smoothing
 684                    rospy.loginfo("IDLE complete → PRE-ALIGN_HEADING_TO_CORRIDOR")
 685                    self.state = PRE_ALIGN_HEADING_TO_CORRIDOR
 686                    self.request_local_passability_check_pub.publish(UInt8(data=0)) # disable both until we reach pre-align position state
 687                    self.stop_robot()
 688                    continue
 689            # =================================================
 690            # PRE_ALIGN_HEADING_TO_CORRIDOR
 691            # =================================================    
 692            if self.state == PRE_ALIGN_HEADING_TO_CORRIDOR:
 693                """
 694                PRE_ALIGN_HEADING_TO_CORRIDOR:
 695                to make sure robot heading is roughly toward corridor direction.
 696                Uses slow forward motion + yaw bias.
 697                """ 
 698                rospy.loginfo(" PRE-ALIGN_HEADING_TO_CORRIDOR state")
 699
 700                # no need to check local passability here because it is a rotation state no translation involved
 701
 702                # Lateral error (meters)
 703                lateral_error_in_robot_base = self.corridor_center_x_robot_base
 704                # x_corridor_center_cam is used only once and used in pre-align heading state for aligning heading toward corridor direction
 705                lateral_error_in_cam =  self.x_corridor_center_cam
 706
 707                rospy.loginfo(f"PRE_ALIGN_HEADING: lateral_error in robot base frame ={lateral_error_in_robot_base:.3f}m, lateral_error in camera frame={lateral_error_in_cam:.3f}m")
 708                
 709
 710                 #If we are sufficiently centered, move to PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR
 711                if abs(lateral_error_in_cam) < self.lateral_error_tolerance_pre_align_heading_state:  # 5 cm tolerance
 712                    rospy.loginfo("PRE_ALIGN_HEADING complete → PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR")
 713                    self.stop_robot()
 714                    self.state = PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR
 715                    continue
 716
 717
 718
 719                # Yaw bias steers robot toward corridor center
 720                omega = self.kp_lateral_movement_pre_align_heading_state * lateral_error_in_cam
 721                omega = np.clip(omega, -self.omega_max_pre_align_heading_state, self.omega_max_pre_align_heading_state)
 722
 723                
 724                self.publish_cmd_vel(0.0 , 0.0, omega)
 725
 726            # =================================================
 727            # PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR
 728            # =================================================  
 729            if self.state == PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR:
 730                """
 731                 to adjust robot's orientation so that the robot will be within the corridor axis, within traveling a particular fraction of distance to the door. 
 732                """
 733                rospy.loginfo(" PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR state")
 734
 735                # no need to check local passability here because it is a rotation state no translation involved
 736
 737                lateral_error_in_robot_base = self.corridor_center_x_robot_base
 738                estimated_forward_distance_to_reach_corridor = lateral_error_in_robot_base / np.tan(self.current_yaw)
 739                maximum_allowable_forward_distance_to_reach_corridor = abs(self.distance_to_corridor_mid_point * self.fraction_distance_to_corridor_mid_point_for_readjust_heading_state) 
 740                distance_offset = abs(estimated_forward_distance_to_reach_corridor) - maximum_allowable_forward_distance_to_reach_corridor
 741                rospy.loginfo(f"PRE_ALIGN_READJUST_HEADING: lateral_error={lateral_error_in_robot_base:.3f} m, estimated_forward_distance_to_reach_corridor={estimated_forward_distance_to_reach_corridor:.3f} m, maximum_allowable_forward_distance_to_reach_corridor={maximum_allowable_forward_distance_to_reach_corridor:.3f} m, distance_offset={distance_offset:.3f} m")
 742                if distance_offset <= 0.1: # will reach corridor within allowable distance
 743                    rospy.loginfo("PRE_ALIGN_READJUST_HEADING complete → PRE-ALIGN_POSITION_TO_CORRIDOR")
 744                    self.stop_robot()
 745                    self.state = PRE_ALIGN_POSITION_TO_CORRIDOR
 746                    self.movement_is_started = False
 747                    # set reference heading for position pre-alignment
 748                    self.pre_align_position_heading_ref = self.current_yaw
 749                    self.request_local_passability_check_pub.publish(UInt8(data=2)) # request local passability check
 750                    continue
 751                
 752
 753                # Yaw bias steers robot toward corridor center
 754                omega = self.kp_lateral_movement_pre_align_readjust_heading_state * distance_offset * np.sign(lateral_error_in_robot_base)
 755                omega = np.clip(omega, -self.omega_max_pre_align_readjust_heading_state, self.omega_max_pre_align_readjust_heading_state)
 756                
 757                self.publish_cmd_vel(0.0 , 0.0, omega)
 758                
 759
 760
 761
 762
 763            # =================================================
 764            # PRE_ALIGN_POSITION_TO_CORRIDOR
 765            # =================================================  
 766            if self.state == PRE_ALIGN_POSITION_TO_CORRIDOR:
 767                """
 768                 to make sure that robot's body is roughly inside in the corridor.
 769                """
 770                rospy.loginfo(" PRE-ALIGN_POSITION_TO_CORRIDOR state")
 771
 772                if not self.local_passable: 
 773                    if not self.movement_is_started: 
 774                        rospy.loginfo("PRE-ALIGN_POSITION_TO_CORRIDOR: waiting for temporal smoothing to finish")
 775                        #stay where you are
 776                        self.stop_robot()
 777                        continue
 778                    else:
 779                        # if passability lost here means, movement were already started and then passabililty lost( that is self.local_passable is False not due to temporal smoothing)
 780                        # temporal smoothing already done and also hysteresis done in passability callback
 781                        # so if the passability is lost here, means it is not safe to move forward( it is not due to glitch )
 782                        # but since we are at pre-align position state, we dont have to abort immediately. robot can still go to align state and then check passability again.
 783                        rospy.logwarn("Passability lost → going to ALIGN_TO_CORRIDOR")
 784                        self.stop_robot()
 785                        self.pre_align_position_heading_ref = 0.0
 786                        self.state = ALIGN_TO_CORRIDOR
 787                        self.movement_is_started = False
 788                        continue
 789                        
 790
 791                self.movement_is_started = True
 792
 793                lateral_error_in_robot_base = self.corridor_center_x_robot_base
 794                rospy.loginfo(f"PRE-ALIGN_POSITION_TO_CORRIDOR: lateral_error={lateral_error_in_robot_base:.3f} m")
 795                # If we are sufficiently centered, move to ALIGN
 796                if abs(lateral_error_in_robot_base) < self.lateral_error_tolerance_pre_align_position_state:  # 5 cm tolerance
 797                    rospy.loginfo("PRE-ALIGN_POSITION_TO_CORRIDOR complete → ALIGN_TO_CORRIDOR")
 798                    self.stop_robot()
 799                    self.state = ALIGN_TO_CORRIDOR
 800                    self.pre_align_position_heading_ref = 0.0
 801                    self.movement_is_started = False
 802                    self.request_local_passability_check_pub.publish(UInt8(data=0)) # disable both until we reach traverse state
 803                    continue
 804
 805                # Heading hold (NOT lateral correction)
 806                heading_error = self.wrap_angle(self.current_yaw - self.pre_align_position_heading_ref)
 807
 808                # Yaw bias steers robot toward corridor center
 809                omega = self.kp_lateral_movement_pre_align_position_state * heading_error
 810                omega = np.clip(omega, -self.omega_max_pre_align_position_state, self.omega_max_pre_align_position_state)
 811
 812                
 813                self.publish_cmd_vel(self.velocity_pre_align_position_state, 0.0, omega)
 814
 815            # =================================================
 816            # ALIGN_TO_CORRIDOR
 817            # =================================================    
 818            elif self.state == ALIGN_TO_CORRIDOR:
 819                """
 820                ALIGN:
 821                Correct heading so robot faces corridor direction.
 822                Uses rotation + minimal creep.
 823                """
 824                rospy.loginfo("  ALIGN_TO_CORRIDOR state")
 825
 826                # no need to check local passability here because it is a rotation state no translation involved
 827                
 828
 829                rospy.loginfo(f"ALIGN: current yaw is {self.current_yaw:.3f} rad, heading_error_to_corridor={self.heading_error_to_corridor:.3f} rad")
 830            
 831                # If heading is good enough, start traversal
 832                if abs(self.heading_error_to_corridor) < self.heading_error_tolerance_align_state: # heading error tolerance
 833                    # but the lateral error may be still high, if the align state is reached from pre-align position state due to passability loss
 834                    lateral_error_in_robot_base = self.corridor_center_x_robot_base
 835                    #to check if the lateral error is also within tolerance. if not means we are not means robot body is not within corridor axis
 836                    if abs(lateral_error_in_robot_base) <= self.lateral_error_tolerance_align_state:  # half of the width of robot in meters
 837                        rospy.loginfo("ALIGN complete → TRAVERSE_DOOR")
 838                        self.stop_robot()
 839
 840                        # Reset traversal reference
 841                        self.movement_is_started = False
 842                        self.state = TRAVERSE_DOOR
 843                        #exit action of ALIGN state
 844                        self.request_local_passability_check_pub.publish(UInt8(data=1)) # check corridor passability
 845                        continue
 846                    else:
 847                        rospy.loginfo("ALIGN_TO_CORRIDOR: lateral error too high → PRE_ALIGN_HEADING_TO_CORRIDOR")
 848                        self.stop_robot()
 849                        self.state = PRE_ALIGN_HEADING_TO_CORRIDOR
 850                        #restart from pre-align heading state
 851                        self.pre_align_position_heading_ref = 0.0
 852                        self.movement_is_started = False
 853                        self.request_local_passability_check_pub.publish(UInt8(data=0)) # disable both 
 854                        continue
 855
 856                # Rotate to reduce lateral error
 857                omega = self.kp_heading_align_state * self.heading_error_to_corridor
 858                omega = np.clip(omega, -self.omega_max_align_state, self.omega_max_align_state)
 859
 860                # Very small forward creep to stabilize yaw estimation
 861
 862                self.publish_cmd_vel(0.0, 0.0, omega)
 863
 864            # =================================================
 865            # TRAVERSE_DOOR
 866            # =================================================
 867            elif self.state == TRAVERSE_DOOR:
 868                rospy.loginfo(" TRAVERSE_DOOR state")
 869                
 870                if not self.corridor_passable:
 871                    if not self.movement_is_started: 
 872                        rospy.loginfo("TRAVERSE_DOOR: waiting for temporal smoothing to finish")
 873                        #stay where you are
 874                        self.stop_robot()
 875                        continue
 876                    else:
 877                        # if passability lost here means, traversal were already started and then passabililty lost( that is self.corridor_passable is False not due to temporal smoothing)
 878                        # temporal smoothing already done and also hysteresis done in passability callback
 879                        # so if the passability is lost here, we abort immediately( it is not due to glitch )
 880                        if self.virtual_corridor_definition_requested_from_traversal_node is False:
 881                            rospy.logwarn("Passability lost → ABORT")
 882                            self.stop_robot()
 883                            self.state = ABORT
 884                            self.movement_is_started = False
 885                            continue
 886                        else:
 887                            rospy.logwarn("Passability lost but virtual corridor definition already requested → LOOK_FOR_A_VIRTUAL_CORRIDOR")
 888                            self.stop_robot()
 889                            self.movement_is_started = False
 890                            distance_to_move_beyond_corridor_mid_point = self.distance_to_corridor_mid_point + self.minimum_clearance_beyond_corridor_mid_point + self.robot_length #because if the door open outward, we need to move sufficiently forward to be beyond the door swing area. also since the camera is on the head, we need to make sure the body ( behind) is beyond the door frame
 891                            self.request_local_passability_check_pub.publish(UInt8(data=2)) # request local passability check
 892                            self.state = MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT
 893                            # set reference  for move after crossing corridor midpoint state.
 894                            # here virtual corridor is not passable now. but we consider it as mid point is reached so that we can go the next state
 895                            # here actually we didnt reach the mid point thats why value of self.distance_to_corridor_mid_point is added to distance_to_move_beyond_corridor_mid_point. 
 896                            #until now the traversal 
 897                            self.start_pose_at_corridor_mid_point = self.current_pose
 898                            self.start_yaw_at_corridor_mid_point = self.current_yaw
 899                            continue
 900
 901
 902                self.movement_is_started = True
 903                
 904                # -----------------------------
 905                # Completion check
 906                # -----------------------------
 907                if self.distance_to_corridor_mid_point <= 0.3: # within 5 cm of door plane. now no chance to collide with closed glass door half
 908                    #at this point we also ensured that corridor in front has a clearance requested from passability node
 909                    rospy.loginfo("Door traversal DONE")
 910                    self.stop_robot()
 911                    self.movement_is_started = False
 912                    distance_to_move_beyond_corridor_mid_point = self.minimum_clearance_beyond_corridor_mid_point + self.robot_length #because if the door open outward, we need to move sufficiently forward to be beyond the door swing area. also since the camera is on the head, we need to make sure the body ( behind) is beyond the door frame
 913                    self.request_local_passability_check_pub.publish(UInt8(data=2)) # request local passability check
 914                    self.state = MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT
 915                    
 916                    # set reference  for move after crossing corridor midpoint state.
 917                    #until now the traversal 
 918                    self.start_pose_at_corridor_mid_point = self.current_pose
 919                    self.start_yaw_at_corridor_mid_point = self.current_yaw
 920                    continue
 921                    #self.state = DONE
 922                    #self.done_pub.publish(Bool(data=True))
 923
 924                now = rospy.Time.now().to_sec()
 925                #guard
 926                if self.prev_time is None:
 927                    self.prev_time = now
 928                    self.prev_corridor_center_x = self.corridor_center_x_robot_base
 929                    continue
 930                
 931                dt = now - self.prev_time
 932                if dt <= 0.0:
 933                    continue
 934                
 935                # lateral offset from corridor center
 936                x_c = self.corridor_center_x_robot_base
 937                heading_error_correction = 0.0 - self.heading_error_to_corridor
 938                x_p_error = 0.0 - x_c  # desired corridor center is at x=0 in robot base frame
 939
 940                # ------------------------------------------------
 941                # Lateral rate ( yaw damping)
 942                # ------------------------------------------------
 943                x_dot = (x_c - self.prev_corridor_center_x) / dt
 944                # ------------------------------------------------
 945                # Angular velocity command (NO heading estimation)
 946                # ------------------------------------------------
 947                rospy.loginfo(f"TRAVERSE_DOOR: lateral error={x_c:.3f} m, lateral_kp_error={x_p_error:.3f} m, lateral error rate={x_dot:.3f} m/s")
 948                omega = (
 949                    self.kp_corridor_center_traverse_state * x_p_error + 
 950                    self.kp_heading_traverse_state * heading_error_correction +
 951                    self.kd_corridor_center_traverse_state * x_dot
 952                )   
 953                omega = np.clip(omega, -self.omega_max_traverse_state, self.omega_max_traverse_state)
 954                # -----------------------------
 955                # Compute velocities
 956                # -----------------------------
 957                velocity_forward = min(self.v_max_traverse_state,
 958                        self.k_clearance_traverse_state * self.front_clearance)
 959                velocity_forward = max(self.v_min_traverse_state, velocity_forward)
 960            
 961
 962                
 963                self.publish_cmd_vel(velocity_forward, 0.0, omega)
 964                # ------------------------------------------------
 965                # State update
 966                # ------------------------------------------------
 967                self.prev_corridor_center_x = x_c
 968                self.prev_time = now
 969
 970
 971                    
 972            # =================================================
 973            # MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT
 974            # =================================================
 975            elif self.state == MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT:
 976                rospy.loginfo(" MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT state")
 977                # donot use the heading error from passability node. because we requested for local passability check just for checking the clearance in front after crossing the door plane. hence heading error estimation is no longer available.
 978                # so we use the last heading and pose from traverse state as reference 
 979                # calculating forward displacment along the heading direction at the time when we just crossed the corridor mid point (door plane). i.e in world frame( corridor frame no longer exists)

 990                        # temporal smoothing already done and also hysteresis done in passability callback
 991                        # so if the passability is lost here, we abort immediately( it is not due to glitch )

1002                            msg.linear.y = 0.25  # corridor is of 0.5m
1003                            # because we cannot give very low value as corridor as defining a new corridor use back projection and it has some minimum depth limit
1004                        else:

1023                    self.stop_robot()
1024                    self.movement_is_started = False
1025                    self.state = DONE
1026                    continue

1029                # Yaw bias steers robot toward corridor center
1030                # cannot use  self.heading_error_to_corridor, because in this state we are in local passability check. hence the heading error estimation from passability node is no longer available. but we can still use the current yaw and the yaw at the time when we just crossed the corridor mid point to do heading hold to make sure the robot is moving along the right direction after crossing the door plane. because if the robot drifts too much in heading after crossing the door plane, it may collide with the door frame half or it may go out of the new corridor after crossing the door plane.

1043            # =================================================

1073                    dy = self.current_pose[1] - backoff_start[1]

 351    def passability_callback(self, msg):
 352        """
 353        Update corridor geometry and filter the latest passability result.
 354
 355        ``type_of_passability_check`` selects one of two independent results.
 356        Type ``1`` verifies clearance through and beyond the corridor midpoint;
 357        type ``2`` verifies only the minimum local clearance. Consecutive safe
 358        or unsafe samples are required before either stored result changes.
 359
 360        Args:
 361            msg:
 362                ``Robot_passability`` message. Distances are expected in
 363                meters, lateral offsets use the camera or initial-yaw frames
 364                named by their fields, and ``heading_error`` is in radians.
 365
 366        Notes:
 367            Receiving one check type clears the counters and result belonging
 368            to the other type. This prevents a stale local result from being
 369            treated as a current corridor result, or vice versa.
 370        """
 371        self.front_clearance = msg.front_clearance
 372        self.corridor_center_x_robot_base = msg.x_corridor_center_start_yaw_frame
 373        self.x_corridor_center_cam = msg.x_corridor_center_cam
 374        self.distance_to_corridor_mid_point = msg.corridor_middle_point_depth
 375        self.minimum_clearance_beyond_corridor_mid_point = msg.clearance_needed_beyond_mid_corridor
 376        self.heading_error_to_corridor = msg.heading_error
 377
 378        # Raw passability from detector
 379        if msg.type_of_passability_check == 1.0: # corridor passability check
 380            self.local_passable = False  # reset local passability. because we are doing corridor passability check now
 381            self.safe_seq_local = 0
 382            self.unsafe_seq_local = 0
 383            
 384            if self.front_clearance is not None:
 385                if self.front_clearance > self.distance_to_corridor_mid_point +self.minimum_clearance_beyond_corridor_mid_point: # ensure there is enough clearance beyond the corridor mid point, not just at the current position, to avoid the case where the robot is currently in a safe spot but will soon collide with the door frame when it moves forward:
 386                    raw_corridor_passable = True
 387                else: 
 388                    raw_corridor_passable = False
 389            else:
 390                raw_corridor_passable = False
 391
 392            # Apply hysteresis: require consecutive confirmations before toggling
 393            if raw_corridor_passable:
 394                self.safe_seq_corridor += 1
 395                self.unsafe_seq_corridor = 0
 396                if self.safe_seq_corridor >= self.passability_true_hysteresis:
 397                    self.corridor_passable = True
 398                        
 399            else:
 400                self.unsafe_seq_corridor += 1
 401                self.safe_seq_corridor = 0
 402                if self.unsafe_seq_corridor >= self.passability_false_hysteresis:
 403                    self.corridor_passable = False
 404            
 405             
 406        elif msg.type_of_passability_check == 2.0: # local passability check
 407            self.corridor_passable = False  # reset corridor passability. because we are doing local passability check now
 408            self.safe_seq_corridor = 0
 409            self.unsafe_seq_corridor = 0
 410            if self.front_clearance is not None:
 411                if self.front_clearance > self.min_front_clearance_local_passability_check:
 412                    raw_local_passable = True
 413                else: 
 414                    raw_local_passable = False
 415            else:
 416                raw_local_passable = False
 417            
 418            # Apply hysteresis: require consecutive confirmations before toggling                  
 419            if raw_local_passable:
 420                self.safe_seq_local += 1
 421                self.unsafe_seq_local = 0
 422                if self.safe_seq_local >= self.passability_true_hysteresis:
 423                    self.local_passable = True
 424            else:
 425                self.unsafe_seq_local += 1
 426                self.safe_seq_local = 0
 427                if self.unsafe_seq_local >= self.passability_false_hysteresis:
 428                    self.local_passable = False

 480    def wrap_angle(self, angle):
 481        """
 482        Normalize an angle to the principal signed range.
 483
 484        Args:
 485            angle:
 486                Angle in radians. Scalars and NumPy-compatible arrays are
 487                accepted.

 495    def publish_cmd_vel(self, v_forward, v_lateral, omega):
 496        """
 497        Apply a robot-frame velocity command to the Gazebo model.
 498
 499        Linear velocity is rotated into the world frame while angular velocity
 500        remains a yaw rate about the world z axis. The latest Gazebo pose is
 501        copied into the request so the service changes velocity without
 502        teleporting the robot.
 503
 504        Args:
 505            v_forward:
 506                Forward velocity in the robot frame, in meters per second.
 507
 508            v_lateral:
 509                Lateral velocity in the robot frame, in meters per second.
 510
 511            omega:
 512                Yaw rate in radians per second.
 513
 514        Raises:
 515            rospy.ServiceException:
 516                If the Gazebo service call fails.
 517
 518        Notes:
 519            The command is skipped when no Gazebo pose has been received. The
 520            world-frame conversion uses the latest odometry yaw.
 521        """
 522
 523        if self.gazebo_pose is None:
 524            rospy.logwarn("Gazebo pose not yet received; cannot publish velocity and angular velocity to /set_model_state service")
 525            return
 526
 527       # DO NOT TOUCH pose at all
 528        self.modelstate.model_name = "go1_gazebo"
 529        self.modelstate.reference_frame = "world"
 530
 531        # always use current gazebo pose
 532        self.modelstate.pose = self.gazebo_pose
 533
 534        # Convert body-frame forward velocity to world frame
 535        # only forward velocity v is given in robot base frame no lateral velocity
 536        #v_lateral is always zero.
 537        vx_world = v_forward * np.cos(self.current_yaw) - v_lateral * np.sin(self.current_yaw)
 538        vy_world = v_forward * np.sin(self.current_yaw) + v_lateral * np.cos(self.current_yaw)
 539
 540        self.modelstate.twist.linear.x = vx_world
 541        self.modelstate.twist.linear.y = vy_world
 542        self.modelstate.twist.linear.z = 0.0
 543
 544        self.modelstate.twist.angular.x = 0.0
 545        self.modelstate.twist.angular.y = 0.0
 546        self.modelstate.twist.angular.z = omega
 547
 548        rospy.loginfo("Publishing cmd_vel: v_forward=%.3f m/s, v_lateral=%.3f m/s, omega=%.3f rad/s", v_forward, v_lateral, omega)
 549
 550        response = self.set_model_state(self.modelstate)
 551        rospy.loginfo(
 552            "Service response: success=%s message=%s",
 553            response.success,
 554            response.status_message
 555        )

 557    def get_forward_displacement(self, ref_pose, ref_yaw):
 558        """
 559        Measure displacement along a fixed reference heading.
 560
 561        The current world-frame translation is projected onto the heading that
 562        was active when the reference pose was recorded. Later yaw corrections
 563        therefore do not change the meaning of the travelled distance.
 564
 565        Args:
 566            ref_pose:
 567                Reference planar position as ``(x, y)`` in meters.
 568
 569            ref_yaw:
 570                Reference heading in radians.
 571
 572        Returns:
 573            Signed forward displacement in meters, or ``0.0`` when current
 574            odometry is not available.
 575        """
 576        if self.current_pose is None:
 577            return 0.0
 578
 579        dx = self.current_pose[0] - ref_pose[0]
 580        dy = self.current_pose[1] - ref_pose[1]
 581
 582        return dx * np.cos(ref_yaw) + dy * np.sin(ref_yaw)

 584    def find_heading_error_estimate(self):
 585        """
 586        Update the motion-based estimate of corridor heading error.
 587
 588        Lateral corridor-center drift is divided by measured forward motion and
 589        passed through a first-order low-pass filter. Updates are accepted only
 590        after enough forward displacement to avoid amplifying stationary
 591        measurement noise.
 592
 593        Notes:
 594            The method updates ``heading_error_est``,
 595            ``heading_estimate_samples``, and ``heading_estimate_valid`` in
 596            place. It does not return the estimate.
 597        """
 598        # Estimate heading error based on change in corridor center x
 599        # =================================================
 600        # Update heading error estimate (from corridor drift and motion-gated)
 601        # =================================================
 602        if (
 603            self.prev_corridor_center_x_robot_base is not None and
 604            self.prev_pose_for_heading is not None and
 605            self.current_pose is not None
 606            ):
 607            # Compute actual forward motion
 608            dx_world = self.current_pose[0] - self.prev_pose_for_heading[0]
 609            dy_world = self.current_pose[1] - self.prev_pose_for_heading[1]
 610
 611            forward_motion = (
 612                dx_world * np.cos(self.current_yaw) +
 613                dy_world * np.sin(self.current_yaw)
 614            )
 615
 616            # Only update heading if robot actually moved forward
 617            if abs(forward_motion) > self.min_forward_motion_for_heading:
 618                lateral_drift = self.corridor_center_x_robot_base - self.prev_corridor_center_x_robot_base
 619                heading_raw = lateral_drift / forward_motion
 620
 621                self.heading_error_est = (
 622                    self.heading_filter_alpha * heading_raw +
 623                    (1.0 - self.heading_filter_alpha) * self.heading_error_est
 624                )
 625                rospy.loginfo(f"Heading error estimate: {self.heading_error_est:.3f} rad")
 626                
 627                self.heading_estimate_samples += 1
 628                if self.heading_estimate_samples >= self.required_heading_samples:
 629                    self.heading_estimate_valid = True
 630
 631                self.prev_corridor_center_x_robot_base = self.corridor_center_x_robot_base
 632                self.prev_pose_for_heading = self.current_pose

 639    def control_loop(self):
 640        """
 641        Run the door-alignment and traversal finite-state machine.
 642
 643        The loop waits for a trigger and valid feedback, performs two heading
 644        alignment stages and one position-alignment stage, turns to the final
 645        corridor heading, traverses the corridor, and continues beyond its
 646        midpoint. Unsafe feedback causes either an abort/back-off or a request
 647        for a virtual corridor, depending on where the robot is in the
 648        sequence.
 649
 650        Raises:
 651            rospy.ServiceException:
 652                If a Gazebo model-state command cannot be delivered.
 653
 654        Notes:
 655            This is a blocking loop intended to run for the lifetime of the
 656            node. It returns after the ``ABORT`` or ``DONE`` state completes,
 657            or when ROS shuts down.
 658        """
 659             
 660
 661        while not rospy.is_shutdown():
 662            if not self.start_movement:# node is activated as there is a corridor to traverse
 663                self.rate.sleep()
 664                continue
 665            
 666            if not self.data_ready():
 667                self.rate.sleep()
 668                continue
 669            
 670        
 671            # =================================================
 672            # IDLE - to wait until temporal smoothing for passability is done
 673            # ================================================= 
 674
 675            if self.state == IDLE:
 676                # Initialize traversal start pose
 677                self.start_pose = self.current_pose
 678                self.start_yaw = self.current_yaw
 679                if not self.corridor_passable:
 680                    rospy.loginfo("IDLE: waiting for temporal smoothing to finish")
 681                    #stay where you are
 682                    self.stop_robot()
 683                    continue
 684                else:#now we are sure the corridor is passable by temporal smoothing
 685                    rospy.loginfo("IDLE complete → PRE-ALIGN_HEADING_TO_CORRIDOR")
 686                    self.state = PRE_ALIGN_HEADING_TO_CORRIDOR
 687                    self.request_local_passability_check_pub.publish(UInt8(data=0)) # disable both until we reach pre-align position state
 688                    self.stop_robot()
 689                    continue
 690            # =================================================
 691            # PRE_ALIGN_HEADING_TO_CORRIDOR
 692            # =================================================    
 693            if self.state == PRE_ALIGN_HEADING_TO_CORRIDOR:
 694                """
 695                PRE_ALIGN_HEADING_TO_CORRIDOR:
 696                to make sure robot heading is roughly toward corridor direction.
 697                Uses slow forward motion + yaw bias.
 698                """ 
 699                rospy.loginfo(" PRE-ALIGN_HEADING_TO_CORRIDOR state")
 700
 701                # no need to check local passability here because it is a rotation state no translation involved
 702
 703                # Lateral error (meters)
 704                lateral_error_in_robot_base = self.corridor_center_x_robot_base
 705                # x_corridor_center_cam is used only once and used in pre-align heading state for aligning heading toward corridor direction
 706                lateral_error_in_cam =  self.x_corridor_center_cam
 707
 708                rospy.loginfo(f"PRE_ALIGN_HEADING: lateral_error in robot base frame ={lateral_error_in_robot_base:.3f}m, lateral_error in camera frame={lateral_error_in_cam:.3f}m")
 709                
 710
 711                 #If we are sufficiently centered, move to PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR
 712                if abs(lateral_error_in_cam) < self.lateral_error_tolerance_pre_align_heading_state:  # 5 cm tolerance
 713                    rospy.loginfo("PRE_ALIGN_HEADING complete → PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR")
 714                    self.stop_robot()
 715                    self.state = PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR
 716                    continue
 717
 718
 719
 720                # Yaw bias steers robot toward corridor center
 721                omega = self.kp_lateral_movement_pre_align_heading_state * lateral_error_in_cam
 722                omega = np.clip(omega, -self.omega_max_pre_align_heading_state, self.omega_max_pre_align_heading_state)
 723
 724                
 725                self.publish_cmd_vel(0.0 , 0.0, omega)
 726
 727            # =================================================
 728            # PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR
 729            # =================================================  
 730            if self.state == PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR:
 731                """
 732                 to adjust robot's orientation so that the robot will be within the corridor axis, within traveling a particular fraction of distance to the door. 
 733                """
 734                rospy.loginfo(" PRE_ALIGN_READJUST_HEADING_TO_CORRIDOR state")
 735
 736                # no need to check local passability here because it is a rotation state no translation involved
 737
 738                lateral_error_in_robot_base = self.corridor_center_x_robot_base
 739                estimated_forward_distance_to_reach_corridor = lateral_error_in_robot_base / np.tan(self.current_yaw)
 740                maximum_allowable_forward_distance_to_reach_corridor = abs(self.distance_to_corridor_mid_point * self.fraction_distance_to_corridor_mid_point_for_readjust_heading_state) 
 741                distance_offset = abs(estimated_forward_distance_to_reach_corridor) - maximum_allowable_forward_distance_to_reach_corridor
 742                rospy.loginfo(f"PRE_ALIGN_READJUST_HEADING: lateral_error={lateral_error_in_robot_base:.3f} m, estimated_forward_distance_to_reach_corridor={estimated_forward_distance_to_reach_corridor:.3f} m, maximum_allowable_forward_distance_to_reach_corridor={maximum_allowable_forward_distance_to_reach_corridor:.3f} m, distance_offset={distance_offset:.3f} m")
 743                if distance_offset <= 0.1: # will reach corridor within allowable distance
 744                    rospy.loginfo("PRE_ALIGN_READJUST_HEADING complete → PRE-ALIGN_POSITION_TO_CORRIDOR")
 745                    self.stop_robot()
 746                    self.state = PRE_ALIGN_POSITION_TO_CORRIDOR
 747                    self.movement_is_started = False
 748                    # set reference heading for position pre-alignment
 749                    self.pre_align_position_heading_ref = self.current_yaw
 750                    self.request_local_passability_check_pub.publish(UInt8(data=2)) # request local passability check
 751                    continue
 752                
 753
 754                # Yaw bias steers robot toward corridor center
 755                omega = self.kp_lateral_movement_pre_align_readjust_heading_state * distance_offset * np.sign(lateral_error_in_robot_base)
 756                omega = np.clip(omega, -self.omega_max_pre_align_readjust_heading_state, self.omega_max_pre_align_readjust_heading_state)
 757                
 758                self.publish_cmd_vel(0.0 , 0.0, omega)
 759                
 760
 761
 762
 763
 764            # =================================================
 765            # PRE_ALIGN_POSITION_TO_CORRIDOR
 766            # =================================================  
 767            if self.state == PRE_ALIGN_POSITION_TO_CORRIDOR:
 768                """
 769                 to make sure that robot's body is roughly inside in the corridor.
 770                """
 771                rospy.loginfo(" PRE-ALIGN_POSITION_TO_CORRIDOR state")
 772
 773                if not self.local_passable: 
 774                    if not self.movement_is_started: 
 775                        rospy.loginfo("PRE-ALIGN_POSITION_TO_CORRIDOR: waiting for temporal smoothing to finish")
 776                        #stay where you are
 777                        self.stop_robot()
 778                        continue
 779                    else:
 780                        # if passability lost here means, movement were already started and then passabililty lost( that is self.local_passable is False not due to temporal smoothing)
 781                        # temporal smoothing already done and also hysteresis done in passability callback
 782                        # so if the passability is lost here, means it is not safe to move forward( it is not due to glitch )
 783                        # but since we are at pre-align position state, we dont have to abort immediately. robot can still go to align state and then check passability again.
 784                        rospy.logwarn("Passability lost → going to ALIGN_TO_CORRIDOR")
 785                        self.stop_robot()
 786                        self.pre_align_position_heading_ref = 0.0
 787                        self.state = ALIGN_TO_CORRIDOR
 788                        self.movement_is_started = False
 789                        continue
 790                        
 791
 792                self.movement_is_started = True
 793
 794                lateral_error_in_robot_base = self.corridor_center_x_robot_base
 795                rospy.loginfo(f"PRE-ALIGN_POSITION_TO_CORRIDOR: lateral_error={lateral_error_in_robot_base:.3f} m")
 796                # If we are sufficiently centered, move to ALIGN
 797                if abs(lateral_error_in_robot_base) < self.lateral_error_tolerance_pre_align_position_state:  # 5 cm tolerance
 798                    rospy.loginfo("PRE-ALIGN_POSITION_TO_CORRIDOR complete → ALIGN_TO_CORRIDOR")
 799                    self.stop_robot()
 800                    self.state = ALIGN_TO_CORRIDOR
 801                    self.pre_align_position_heading_ref = 0.0
 802                    self.movement_is_started = False
 803                    self.request_local_passability_check_pub.publish(UInt8(data=0)) # disable both until we reach traverse state
 804                    continue
 805
 806                # Heading hold (NOT lateral correction)
 807                heading_error = self.wrap_angle(self.current_yaw - self.pre_align_position_heading_ref)
 808
 809                # Yaw bias steers robot toward corridor center
 810                omega = self.kp_lateral_movement_pre_align_position_state * heading_error
 811                omega = np.clip(omega, -self.omega_max_pre_align_position_state, self.omega_max_pre_align_position_state)
 812
 813                
 814                self.publish_cmd_vel(self.velocity_pre_align_position_state, 0.0, omega)
 815
 816            # =================================================
 817            # ALIGN_TO_CORRIDOR
 818            # =================================================    
 819            elif self.state == ALIGN_TO_CORRIDOR:
 820                """
 821                ALIGN:
 822                Correct heading so robot faces corridor direction.
 823                Uses rotation + minimal creep.
 824                """
 825                rospy.loginfo("  ALIGN_TO_CORRIDOR state")
 826
 827                # no need to check local passability here because it is a rotation state no translation involved
 828                
 829
 830                rospy.loginfo(f"ALIGN: current yaw is {self.current_yaw:.3f} rad, heading_error_to_corridor={self.heading_error_to_corridor:.3f} rad")
 831            
 832                # If heading is good enough, start traversal
 833                if abs(self.heading_error_to_corridor) < self.heading_error_tolerance_align_state: # heading error tolerance
 834                    # but the lateral error may be still high, if the align state is reached from pre-align position state due to passability loss
 835                    lateral_error_in_robot_base = self.corridor_center_x_robot_base
 836                    #to check if the lateral error is also within tolerance. if not means we are not means robot body is not within corridor axis
 837                    if abs(lateral_error_in_robot_base) <= self.lateral_error_tolerance_align_state:  # half of the width of robot in meters
 838                        rospy.loginfo("ALIGN complete → TRAVERSE_DOOR")
 839                        self.stop_robot()
 840
 841                        # Reset traversal reference
 842                        self.movement_is_started = False
 843                        self.state = TRAVERSE_DOOR
 844                        #exit action of ALIGN state
 845                        self.request_local_passability_check_pub.publish(UInt8(data=1)) # check corridor passability
 846                        continue
 847                    else:
 848                        rospy.loginfo("ALIGN_TO_CORRIDOR: lateral error too high → PRE_ALIGN_HEADING_TO_CORRIDOR")
 849                        self.stop_robot()
 850                        self.state = PRE_ALIGN_HEADING_TO_CORRIDOR
 851                        #restart from pre-align heading state
 852                        self.pre_align_position_heading_ref = 0.0
 853                        self.movement_is_started = False
 854                        self.request_local_passability_check_pub.publish(UInt8(data=0)) # disable both 
 855                        continue
 856
 857                # Rotate to reduce lateral error
 858                omega = self.kp_heading_align_state * self.heading_error_to_corridor
 859                omega = np.clip(omega, -self.omega_max_align_state, self.omega_max_align_state)
 860
 861                # Very small forward creep to stabilize yaw estimation
 862
 863                self.publish_cmd_vel(0.0, 0.0, omega)
 864
 865            # =================================================
 866            # TRAVERSE_DOOR
 867            # =================================================
 868            elif self.state == TRAVERSE_DOOR:
 869                rospy.loginfo(" TRAVERSE_DOOR state")
 870                
 871                if not self.corridor_passable:
 872                    if not self.movement_is_started: 
 873                        rospy.loginfo("TRAVERSE_DOOR: waiting for temporal smoothing to finish")
 874                        #stay where you are
 875                        self.stop_robot()
 876                        continue
 877                    else:
 878                        # if passability lost here means, traversal were already started and then passabililty lost( that is self.corridor_passable is False not due to temporal smoothing)
 879                        # temporal smoothing already done and also hysteresis done in passability callback
 880                        # so if the passability is lost here, we abort immediately( it is not due to glitch )
 881                        if self.virtual_corridor_definition_requested_from_traversal_node is False:
 882                            rospy.logwarn("Passability lost → ABORT")
 883                            self.stop_robot()
 884                            self.state = ABORT
 885                            self.movement_is_started = False
 886                            continue
 887                        else:
 888                            rospy.logwarn("Passability lost but virtual corridor definition already requested → LOOK_FOR_A_VIRTUAL_CORRIDOR")
 889                            self.stop_robot()
 890                            self.movement_is_started = False
 891                            distance_to_move_beyond_corridor_mid_point = self.distance_to_corridor_mid_point + self.minimum_clearance_beyond_corridor_mid_point + self.robot_length #because if the door open outward, we need to move sufficiently forward to be beyond the door swing area. also since the camera is on the head, we need to make sure the body ( behind) is beyond the door frame
 892                            self.request_local_passability_check_pub.publish(UInt8(data=2)) # request local passability check
 893                            self.state = MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT
 894                            # set reference  for move after crossing corridor midpoint state.
 895                            # here virtual corridor is not passable now. but we consider it as mid point is reached so that we can go the next state
 896                            # here actually we didnt reach the mid point thats why value of self.distance_to_corridor_mid_point is added to distance_to_move_beyond_corridor_mid_point. 
 897                            #until now the traversal 
 898                            self.start_pose_at_corridor_mid_point = self.current_pose
 899                            self.start_yaw_at_corridor_mid_point = self.current_yaw
 900                            continue
 901
 902
 903                self.movement_is_started = True
 904                
 905                # -----------------------------
 906                # Completion check
 907                # -----------------------------
 908                if self.distance_to_corridor_mid_point <= 0.3: # within 5 cm of door plane. now no chance to collide with closed glass door half
 909                    #at this point we also ensured that corridor in front has a clearance requested from passability node
 910                    rospy.loginfo("Door traversal DONE")
 911                    self.stop_robot()
 912                    self.movement_is_started = False
 913                    distance_to_move_beyond_corridor_mid_point = self.minimum_clearance_beyond_corridor_mid_point + self.robot_length #because if the door open outward, we need to move sufficiently forward to be beyond the door swing area. also since the camera is on the head, we need to make sure the body ( behind) is beyond the door frame
 914                    self.request_local_passability_check_pub.publish(UInt8(data=2)) # request local passability check
 915                    self.state = MOVE_AFTER_CROSSING_CORRIDOR_MIDPOINT
 916                    
 917                    # set reference  for move after crossing corridor midpoint state.
 918                    #until now the traversal 
 919                    self.start_pose_at_corridor_mid_point = self.current_pose
 920                    self.start_yaw_at_corridor_mid_point = self.current_yaw
 921                    continue
 922                    #self.state = DONE
 923                    #self.done_pub.publish(Bool(data=True))
 924
 925                now = rospy.Time.now().to_sec()
 926                #guard
 927                if self.prev_time is None:
 928                    self.prev_time = now

Control the robot while it aligns with and traverses a door corridor.

The controller consumes corridor geometry and passability updates, applies confirmation hysteresis, aligns the robot in stages, and continuously checks clearance while crossing and moving beyond the door. Recovery states either back the robot away from an unsafe corridor or ask the passability node to define a temporary corridor around a newly observed obstruction.

In the current Gazebo integration, velocity commands are converted from the robot frame to world-frame twists and sent through /gazebo/set_model_state.

Run the door-alignment and traversal finite-state machine.

The loop waits for a trigger and valid feedback, performs two heading alignment stages and one position-alignment stage, turns to the final corridor heading, traverses the corridor, and continues beyond its midpoint. Unsafe feedback causes either an abort/back-off or a request for a virtual corridor, depending on where the robot is in the sequence.

Raises: rospy.ServiceException: If a Gazebo model-state command cannot be delivered.

Notes: This is a blocking loop intended to run for the lifetime of the node. It returns after the ABORT or DONE state completes, or when ROS shuts down.
